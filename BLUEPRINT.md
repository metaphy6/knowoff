# 📖 BLUEPRINT.md — pointer stub

> **Read [`docs/planning/ROADMAP.md`](docs/planning/ROADMAP.md) instead.**
> It is the single source of truth: the full product blueprint (game
> rules, tech stack, architecture, media engine, economy, admin console,
> contributor portal, product baseline) as its spec chapters, followed by
> the sequenced **🗺 Roadmap — Step-by-Step Implementation Lifecycle**
> chapter (phases, checkboxes, proof tests, gates) on top.

This file is intentionally just a pointer — it is **not** a second copy of
the spec. Keeping the spec and the roadmap in one document is deliberate:
two files describing the same product will eventually disagree, and
whichever one an agent reads first becomes an accidental source of truth.
See the lockstep rule in `docs/planning/ROADMAP.md`'s Appendix A and
`AGENTS.md` §1.

- Need the product spec, architecture, or design decisions? →
  `docs/planning/ROADMAP.md`, spec chapters (everything before **🗺 Roadmap**).
- Need the implementation plan, phase status, or proof tests? →
  `docs/planning/ROADMAP.md`, roadmap chapter (everything after **🗺 Roadmap**).
- Need a fast, high-level orientation first? → [`README.md`](README.md).

Do not paste spec content back into this file. If this file has drifted
into a second monolith again, trim it back to this stub in the same change.
